# Пары

Живой сайт: https://rasp-is2-241.pages.dev/

Офлайн-расписание занятий ВГЛТУ. Одна ссылка на всю группу: каждый выбирает свой код (ИС2-241-ОБ, ИС2-242-ОБ и любой другой), ставит сайт на экран телефона и открывает пары без интернета.

Дата «сегодня» считается заново при каждом открытии по часам телефона в поясе **Europe/Moscow (UTC+3)**: день, месяц и год. Приложение не оставляет вчерашнюю дату, если на сайте университета форма застыла на предыдущем дне.

## Как открыть одногруппникам

Основная ссылка — расписание и посещаемость:

https://rasp-is2-241.pages.dev/

1. Откройте ссылку.
2. Введите код группы. Подсказка по умолчанию — `ИС2-241-ОБ`, но можно выбрать любую группу из списка.
3. На экране «Сегодня» видны пары: время, предмет, аудитория (например `215Комп/Гл`), преподаватель, тип `лек` / `лаб` / `пр`, если он есть.
4. «Завтра» и «Неделя» ходят по настоящим календарным дням. Чужой день можно набрать полями **день / месяц / год** и нажать «Показать эту дату». Месяц стоит отдельной строкой, чтобы название влезало целиком. Кнопка «К сегодня» возвращает текущую московскую дату.
5. «Неделя» начинается с **сегодня** по Москве и идёт до **воскресенья** этой же календарной недели. Дни до сегодняшнего в список не попадают. Если открыта будущая неделя, видны все её дни с понедельника по воскресенье. Конец недели — воскресенье: в ответе расписания ВГЛТУ воскресенье есть отдельной строкой (часто «Нет пар.»), поэтому суббота за конец недели не принята.

Зеркало только с расписанием, без входа в журнал: https://furfantom1331fur.github.io/rasp-is2-241/

## Офлайн

При первом открытии с интернетом service worker сохраняет страницу, значки и JSON расписания. Дальше «Сегодня» открывается без сети. Внизу экрана написано, когда копия была сохранена.

Пока телефон онлайн, приложение при запуске и при событии `online` снова запрашивает расписание. Выбранная группа запоминается в `localStorage`, расписание группы лежит и в `localStorage`, и в Cache API.

## Как обновить расписание

Интерактивное расписание университета ходит в `https://kis.vgltu.ru`:

- список групп: `https://kis.vgltu.ru/list?type=Group`
- пары: `https://kis.vgltu.ru/schedule?date=ГГГГ-ММ-ДД&group=КОД`

В ответе нет заголовка CORS, поэтому страница на GitHub Pages не может прочитать эти адреса из браузера. Приложение всё равно пробует прямой запрос (если университет откроет CORS, подхватится живой ответ). Пока ответа нет, показывается файл из `data/schedules/`.

Сопровождающий обновляет файлы у себя на компьютере и пушит их в репозиторий:

```bash
python3 scripts/update_schedule.py
python3 scripts/update_schedule.py ИС2-242-ОБ
python3 scripts/update_schedule.py --from 2026-09-21 --weeks 2 ИС2-241-ОБ ИС2-243-ОБ
```

Скрипт сам берёт понедельник текущей московской недели, если `--from` не указан. Каждое окно — 14 дней. Дата в запрос подставляется явно, а не из формы на сайте ВГЛТУ.

В репозитории уже лежат список всех групп и копии на ближайшие недели для `ИС2-241-ОБ`, `ИС2-242-ОБ`, `ИС2-243-ОБ` и `ИС2-244-ОБ`. Для другой группы запустите скрипт с её кодом и закоммитьте новый JSON. После пуша одногруппники получат файл при следующем открытии онлайн.

Проверка дат и разбора пар:

```bash
node scripts/selfcheck.mjs
```

## Посещаемость

Внизу экрана три вкладки: **Расписание**, **Посещаемость**, **Ещё**. «Расписание» открывает сегодняшние пары. Внутри него остаются «Сегодня», «Завтра» и «Неделя».

Журнал повторяет личный кабинет [vgltu.ru/lc/attendance](https://vgltu.ru/lc/attendance): вход по **ID студента** и паролю, затем отметки за семестр или за выбранные даты. ФИО берётся из кабинета и показывается на экране посещаемости. Сверху — сводка: процент `(всего − пропуски) / всего` и число пропусков «Н». Кабинет не присылает часы, поэтому считается каждое занятие в журнале, а не академические часы. Строка без отметки не считается пропуском. Сводка сохраняется вместе с последней копией и видна без сети.

Браузер не может сам вызвать `vgltu.ru` из‑за CORS. Код в `worker/src/index.js` только пересылает кабинет и больше ничего:

- `POST https://vgltu.ru/lc/login` — войти и получить сессию;
- `GET https://vgltu.ru/lc/` и `GET https://vgltu.ru/lc/attendance` — прочитать ФИО из блока `user-info__fio`;
- `GET https://vgltu.ru/lc/site/ajax-attendance-by-date` — журнал (`beginDate` / `endDate`, сначала `ДД.ММ.ГГГГ`, если пусто — `ГГГГ-ММ-ДД`);
- `GET https://vgltu.ru/lc/logout` — завершить сессию на сайте.

На Cloudflare Pages тот же файл отвечает **с адреса сайта**, без `*.workers.dev`:

- `POST /login`
- `GET /attendance`
- `POST /logout`

`WORKER_URL` в `js/config.js` пустой. Тогда приложение само берёт адрес открытой вкладки (`location.origin`, без слэша в конце). Это работает, когда сайт лежит в корне Pages. В интерфейсе адрес не показывается: одногруппники видят только ID и пароль.

Пароль **не записывается** в приложение и не уходит никуда, кроме этого же сайта, а тот сразу отправляет его только на `vgltu.ru`. В `localStorage` остаётся идентификатор сессии `PHPFRONTSESSID` и последняя копия журнала. Копия видна без сети. Кнопка «Выйти» стирает сессию на телефоне и просит кабинет закрыть её тоже. Копия журнала после выхода остаётся, пока не войдёте снова и не обновите её.

Если телефон не достучался до сервера, на экране будет текст «Нет связи с сервером посещаемости…», а не английское `Failed to fetch`.

Живой сайт с расписанием и посещаемостью: `https://rasp-is2-241.pages.dev/`. Вход идёт на `https://rasp-is2-241.pages.dev/login`. GitHub Pages отдаёт только файлы и не может принять `/login`. Зеркало `https://furfantom1331fur.github.io/rasp-is2-241/` открывает только расписание.

### Как выложить на Cloudflare Pages

Раскладка репозитория, её и деплоит Wrangler:

| Путь | Зачем |
| --- | --- |
| корень (`index.html`, `css/`, `js/`, `sw.js`, `data/`, `icons/`) | статический PWA, сайт открывается с `/` |
| `functions/login.js`, `functions/attendance.js`, `functions/logout.js` | Pages Functions: вызывают `worker/src/index.js`, в статику не попадают |
| `functions/_handler.js` | общая точка входа этих трёх путей |
| `worker/` | тот же исходник; секретов в репозитории нет |
| `wrangler.toml` в корне | `pages_build_output_dir = "."` и `compatibility_date` |

Из корня репозитория, после `npx wrangler login` (токен в репозиторий не класть):

```bash
npx wrangler pages deploy . --project-name rasp-is2-241
```

Сайт уже открыт: https://rasp-is2-241.pages.dev/

Команда обновляет этот же проект: собирает `functions/` из текущей папки и заливает остальные файлы корня. Приложение в корне, поэтому вход идёт на `https://rasp-is2-241.pages.dev/login`, а не на GitHub Pages и не на `workers.dev`.

Папка `worker/` для этого деплоя не обязательна. Отдельный `npx wrangler deploy` внутри `worker/` публикует старый кросс-доменный Worker; приложение его больше не вызывает, пока `WORKER_URL` пустой.

## Напоминание

В разделе «Ещё» можно включить местное уведомление за 10 минут до следующей пары. Это Notification API в открытом приложении, без push-сервера. Если разрешение не дали или iOS его ограничивает, расписание всё равно работает.
