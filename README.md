Офлайн-расписание занятий ВГЛТУ. Одна ссылка на всю группу: каждый выбирает свой код (ИС2-241-ОБ, ИС2-242-ОБ и любой другой), ставит сайт на экран телефона и открывает пары без интернета.

Дата «сегодня» считается заново при каждом открытии по часам телефона в поясе **Europe/Moscow (UTC+3)**: день, месяц и год. Приложение не оставляет вчерашнюю дату, если на сайте университета форма застыла на предыдущем дне.

## Как открыть одногруппникам

Основная ссылка — расписание и посещаемость:

https://rasp-is2-241.pages.dev/

1. Откройте ссылку.
2. Введите код группы. Подсказка по умолчанию — `ИС2-241-ОБ`, но можно выбрать любую группу из списка.
3. На экране «Сегодня» видны пары: время, предмет, аудитория (например `215Комп/Гл`), преподаватель, тип `лек` / `лаб` / `пр`, если он есть.
4. Над датой — переключатель **Все / 1 пг / 2 пг**. «Все» показывает каждую пару и ставит значок на занятие одной подгруппы. «1 пг» и «2 пг» оставляют общие пары и пары выбранной подгруппы. Выбор запоминается на этом телефоне и работает без сети. Напоминание за 10 минут и сводка посещаемости считают то же самое.
5. «Завтра» и «Неделя» ходят по настоящим календарным дням. Чужой день можно набрать полями **день / месяц / год** и нажать «Показать эту дату». Месяц стоит отдельной строкой, чтобы название влезало целиком. Кнопка «К сегодня» возвращает текущую московскую дату.
6. «Неделя» начинается с **сегодня** по Москве и идёт до **воскресенья** этой же календарной недели. Дни до сегодняшнего в список не попадают. Если открыта будущая неделя, видны все её дни с понедельника по воскресенье. Конец недели — воскресенье: в ответе расписания ВГЛТУ воскресенье есть отдельной строкой (часто «Нет пар.»), поэтому суббота за конец недели не принята.

Зеркало на GitHub Pages: https://furfantom1331fur.github.io/rasp-is2-241/ — файлы те же, а живое расписание, список групп и вход оно берёт с `https://rasp-is2-241.pages.dev` (CORS).

## Офлайн

При первом открытии с интернетом service worker сохраняет страницу, значки и JSON расписания. Дальше «Сегодня» открывается без сети. Внизу экрана написано, когда копия была сохранена.

При запуске, возвращении сети и вкладки приложение скачивает общие пакеты всех групп
на текущую и следующую недели. Дождитесь «Все группы сохранены» до ухода из сети.
Выбранная группа также обновляется живым запросом. Подробности сборки, хранения и
ограничения описаны в разделе «Офлайн всех групп (версия 18)» ниже.

Что пишет строка статуса:

- «Обновлено с сайта ВГЛТУ …» — свежий ответ через `/schedule`;
- «Нет связи с сервером — показано сохранённое расписание от …» — нет интернета или сервер не ответил;
- «Сайт ВГЛТУ не ответил, показана копия от …» — наш сервер на связи, но kis.vgltu.ru молчит или вернул ошибку;
- «Для этой группы ещё нет сохранённой копии…» — группа ни разу не открывалась с интернетом.

Последняя удачная копия всегда остаётся на экране.

## Обновления приложения

Номер версии виден в разделе «Ещё»: «Версия 18 от 30.10.2026» и кнопка «Проверить обновления» («У вас последняя версия» или «Доступно обновление — версия N»).

Как это работает:

- `version.json` в корне сайта — номер, дата и список изменений. Service worker его не кэширует, приложение запрашивает его с `?t=…` и `cache: "no-store"`: при запуске, при возвращении в приложение (`visibilitychange`, не чаще раза в минуту) и раз в 30 минут, пока оно открыто. Вместе с этим вызывается `registration.update()`.
- Если номер больше `APP_VERSION` из `js/version.js`, внизу появляется баннер «Доступно обновление — версия N» со списком изменений и кнопками «Обновить» / «Позже».
- Новый service worker (`rasp-shell-vN`) заранее скачивает всю новую версию в свой кэш и ждёт. Код кладётся только целиком и только если `version.json` на сайте совпадает с его номером, поэтому старые и новые файлы не смешиваются. Копии расписания переносятся из старого кэша.
- «Обновить» отправляет ждущему worker `skip-waiting`, он включается (`clients.claim`), страница перезагружается ровно один раз. Защита от цикла: не больше одной автоматической перезагрузки на версию за 2 минуты (`sessionStorage`); если обновление не встало, баннер пишет об этом и ждёт повторного нажатия.
- После обновления один раз показывается «Обновлено до версии N» со списком изменений.
- Если нажать «Позже» или закрыть приложение, новая версия включится сама при следующем полном запуске.

### Как выпустить новую версию

1. Поднять номер в трёх местах одинаково: `const SHELL = "rasp-shell-vN"` в `sw.js`, `APP_VERSION` в `js/version.js`, `"version"` в `version.json`.
2. Там же обновить дату (`APP_DATE` / `"date"`) и список изменений (`APP_CHANGES` / `"changes"`) — коротко, по-русски, 1–5 пунктов. Тексты в `js/version.js` и `version.json` должны совпадать.
3. `node scripts/selfcheck.mjs` — проверяет, что номер, дата и список совпадают.
4. PR → merge в `main` (GitHub Pages пересоберётся сам) → `npx wrangler pages deploy . --project-name rasp-is2-241 --branch main` из свежей копии `main`.

Любое изменение кода (`js/`, `css/`, `index.html`, `sw.js`) выпускать только с новым номером: без него телефоны не узнают о новой версии. Ночное обновление `data/` номер не меняет — данные подтягиваются отдельно.

## Как обновить расписание

Интерактивное расписание университета ходит в `https://kis.vgltu.ru`:

- список групп: `https://kis.vgltu.ru/list?type=Group`
- пары: `https://kis.vgltu.ru/schedule?date=ГГГГ-ММ-ДД&group=КОД`

В ответе нет заголовка CORS, поэтому браузер не читает эти адреса напрямую. На Cloudflare Pages тот же домен отвечает через Pages Functions:

- `GET /groups` — список групп (`{ fetchedAt, source, groups: [...] }`, как `data/groups.json`), копия на краю Cloudflare — сутки;
- `GET /schedule?date=ГГГГ-ММ-ДД&group=КОД[&windows=1..3]` — уже разобранные дни (`{ group, fetchedAt, origin: "live", range, days }`). Одно окно — 14 дней с `date`, приложение берёт 2 окна с понедельника. Копия на краю — 45 минут.

Функции (`functions/_kis.js`) ходят к kis.vgltu.ru с `Accept-Encoding: gzip` (без него ответ зависает после ~16 КБ) и таймаутом 8 с. Если ВГЛТУ не ответил, отдаётся устаревшая копия с краю (`"stale": true`), а если её нет — JSON-ошибка `502 upstream_error` или `504 upstream_timeout`. Разбор общий с приложением: `js/parse.js`.

Ночное задание `.github/workflows/update-schedule.yml` теперь собирает общие пакеты всех групп через `scripts/build_bundles.py`; старые индивидуальные снимки автоматически больше не обновляются.

Запустить вручную:

```bash
python3 scripts/update_schedule.py
python3 scripts/update_schedule.py ИС2-242-ОБ
python3 scripts/update_schedule.py --from 2026-09-21 --weeks 2 ИС2-241-ОБ ИС2-243-ОБ
```

Скрипт сам берёт понедельник текущей московской недели, если `--from` не указан. Каждое окно — 14 дней, по умолчанию 3 окна и группы ИС2-241…244-ОБ. Дата в запрос подставляется явно, а не из формы на сайте ВГЛТУ. Между запросами пауза 1 с, при сбое — до трёх попыток.

Все группы также входят в общие недельные пакеты; `/schedule` остаётся для живого обновления выбранной группы.

Проверка дат и разбора пар:

```bash
node scripts/selfcheck.mjs
```

## Посещаемость

Внизу экрана три вкладки: **Расписание**, **Посещаемость**, **Ещё**. «Расписание» открывает сегодняшние пары. Внутри него остаются «Сегодня», «Завтра» и «Неделя».

Журнал повторяет личный кабинет [vgltu.ru/lc/attendance](https://vgltu.ru/lc/attendance): вход по **ID студента** и паролю, затем отметки за семестр или за выбранные даты. ФИО берётся из кабинета и показывается на экране посещаемости. Сверху — сводка: процент `(всего − пропуски) / всего` и число пропусков «Н». Кабинет не присылает часы, поэтому считается каждое занятие в журнале, а не академические часы. Строка без отметки не считается пропуском. Сводка сохраняется вместе с последней копией и видна без сети.

Браузер не может сам вызвать `vgltu.ru` из‑за CORS. Код в `worker/src/index.js` только пересылает кабинет и больше ничего:

- `POST https://vgltu.ru/lc/login` — войти и получить сессию;
- `GET https://vgltu.ru/lc/` и `GET https://vgltu.ru/lc/attendance` — прочитать ФИО из блока `user-info__fio`;
- `GET https://vgltu.ru/lc/site/ajax-attendance-by-date` — журнал (`beginDate` / `endDate`, сначала `ДД.ММ.ГГГГ`, если пусто — `ГГГГ-ММ-ДД`);
- `GET https://vgltu.ru/lc/logout` — завершить сессию на сайте.

На Cloudflare Pages тот же файл отвечает **с адреса сайта**, без `*.workers.dev`:

- `POST /login`
- `GET /attendance`
- `POST /logout`

`WORKER_URL` в `js/config.js` пустой. Тогда приложение само берёт адрес открытой вкладки (`location.origin`, без слэша в конце). Это работает, когда сайт лежит в корне Pages. В интерфейсе адрес не показывается: одногруппники видят только ID и пароль.

Пароль **не записывается** в приложение и не уходит никуда, кроме этого же сайта, а тот сразу отправляет его только на `vgltu.ru`. В `localStorage` остаётся идентификатор сессии `PHPFRONTSESSID` и последняя копия журнала. Копия видна без сети. Кнопка «Выйти» стирает сессию на телефоне и просит кабинет закрыть её тоже. Копия журнала после выхода остаётся, пока не войдёте снова и не обновите её.

Если телефон не достучался до сервера, на экране будет текст «Нет связи с сервером посещаемости…», а не английское `Failed to fetch`.

Живой сайт с расписанием и посещаемостью: `https://rasp-is2-241.pages.dev/`. Вход идёт на `https://rasp-is2-241.pages.dev/login`. GitHub Pages отдаёт только файлы и не может принять `/login`, поэтому зеркало `https://furfantom1331fur.github.io/rasp-is2-241/` отправляет вход и журнал на `https://rasp-is2-241.pages.dev`.

### Как выложить на Cloudflare Pages

Раскладка репозитория, её и деплоит Wrangler:

| Путь | Зачем |
| --- | --- |
| корень (`index.html`, `css/`, `js/`, `sw.js`, `data/`, `icons/`) | статический PWA, сайт открывается с `/` |
| `functions/login.js`, `functions/attendance.js`, `functions/logout.js` | Pages Functions: вызывают `worker/src/index.js`, в статику не попадают |
| `functions/_handler.js` | общая точка входа этих трёх путей |
| `functions/groups.js`, `functions/schedule.js`, `functions/_kis.js` | прокси расписания kis.vgltu.ru на том же домене |
| `version.json`, `js/version.js` | номер версии, дата и список изменений для баннера обновления |
| `404.html` | настоящий 404 вместо index.html для неизвестных путей (иначе service worker клал HTML под адрес JSON) |
| `.github/workflows/update-schedule.yml` | ночное обновление `data/` |
| `worker/` | тот же исходник; секретов в репозитории нет |
| `wrangler.toml` в корне | `pages_build_output_dir = "."` и `compatibility_date` |

Из корня репозитория, после `npx wrangler login` (токен в репозиторий не класть):

```bash
npx wrangler pages deploy . --project-name rasp-is2-241
```

Сайт уже открыт: https://rasp-is2-241.pages.dev/

Команда обновляет этот же проект: собирает `functions/` из текущей папки и заливает остальные файлы корня. Приложение в корне, поэтому вход идёт на `https://rasp-is2-241.pages.dev/login`, а не на GitHub Pages и не на `workers.dev`.

Папка `worker/` для этого деплоя не обязательна. Отдельный `npx wrangler deploy` внутри `worker/` публикует старый кросс-доменный Worker; приложение его больше не вызывает, пока `WORKER_URL` пустой.

## Офлайн всех групп (версия 18)

Телефон скачивает два общих компактных JSON-файла `data/bundles/YYYY-MM-DD.json`:
текущую календарную неделю по Europe/Moscow и следующую. После сообщения
«Все группы сохранены» можно без сети выбрать любую группу из опубликованного списка,
даже ранее не открытую. Выбранная группа показывается из локальной копии сразу;
общая загрузка выполняется отдельно. На больших экранах рабочая область расширена до 720 px.

Пакеты собирает `python3 scripts/build_bundles.py` в GitHub Actions ежедневно в 03:17
Москвы. Это один последовательный запрос к университету на группу на 14 дней,
с паузой 1 секунда и ограниченными повторами, вместо обхода всех групп каждым телефоном.
Для 467 групп обычно нужны десятки минут; лимит задания 90 минут. Успешные ответы
сохраняются в `work/bundle-resume/<московская дата>/` и Actions Cache: повтор задания
в тот же день скачивает только неудавшиеся группы. Старые даты не используются.
Список групп берётся из университета, число не зашито в код.

Для публикации нужны успешные ответы **всех** групп, ровно 14 уникальных дат и
полные таблицы HTML, включая явные пустые выходные. Ошибка даже одной группы
завершает сборку с ошибкой и сохраняет предыдущие опубликованные пакеты. Пустой
или обрезанный ответ не считается подтверждением отсутствия пар. Журнал сборки
показывает фактическое покрытие, ошибки, размер JSON и оценку gzip. JSON записывается
без отступов; HTTPS-хостинг должен включать gzip/Brotli для `application/json`
(Cloudflare обычно делает это автоматически; проверить `Content-Encoding` после деплоя).
Приложение принимает распакованный JSON не более 25 млн символов; точные размеры
зависят от нагрузки расписания и выводятся сборщиком.

Телефон проверяет схему, состав групп, каждую дату и структуру занятий до записи.
Замена одной недели атомарна через Cache API; обрыв, HTTP-ошибка, нехватка места или
неполный пакет не стирают предыдущую рабочую неделю. Если первая неделя загрузилась,
а вторая нет, первая уже доступна, сообщение об ошибке не обещает полной готовности.
Повторяет целиком только нескачанный/обновляемый недельный файл; HTTP Range не требуется.
Проверка запускается при открытии, возвращении вкладки и сети, а также кнопкой
«Обновить»; после успешного обновления ограничена одним разом в час.

В понедельник загруженная следующая неделя становится текущей. Общий кэш хранит
только текущую и следующую, старые удаляются при открытии/синхронизации. Старые
индивидуальные записи мигрируют на тот же диапазон; история недавних групп остаётся
ограниченной десятью. Нет загруженной недели — нет обещания свежего расписания:
приложение показывает статус отсутствующих данных и не подставляет прошлую неделю.
Расписание групп за пределами двух недель не сохраняется; преподаватели и
посещаемость используют прежние отдельные хранилища.

Важно: браузер может удалить данные сайта при очистке хранилища или нехватке места.
Нужно дождаться подтверждения загрузки **до** ухода из сети. Полностью закрытое
приложение не гарантирует скачивания в фоне. Ночная сборка — снимок на время запроса,
изменения университета после неё появятся при следующей сборке или живом обновлении
выбранной группы. Устаревшую по датам неделю приложение не использует как текущую.

Проверки: `node scripts/selfcheck.mjs`, `node scripts/check-bundles.mjs` и
`python3 scripts/check_bundle_builder.py`. В выпуск включены проверенные пакеты 26.10–08.11.2026 для 467/467 групп.
Push в main запускает проверки и публикацию готовых файлов без повторного обхода университета;
ночной запуск и workflow_dispatch пересобирают данные. Нужна публикация файлов вместе с shell v18. GitHub Pages
должен публиковать содержимое main. Cloudflare Direct Upload выполняется workflow
только при наличии `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`; без них обновления
на production не гарантируются. Само наличие файлов в GitHub не подтверждает выпуск на Cloudflare: проверьте успешность шага публикации и version.json действующего сайта.
